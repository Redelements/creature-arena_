### Part 0: mode x map matrix

### Part 1: mode-object leak

Details: `docs/qa/part1-mode-leak.md`. Reproduced first, then fixed.

- **major**, fixed (5e50f65, test 842d7c2): after a Capture the Flag, Caravan or Brawl match,
  the menu background and the next 1v1 kept drawing that match's flags, shrine pads, wagon and
  wanted marks. Repro as a player: play CTF to the results, press Main menu, watch the fight
  behind the title (two flags, three pads); start Versus 1v1 on any map: still there. Root
  cause: `FxView.clear()` (src/view/fx_view.gd) reset only `pads` and `zone`; `flags`,
  `shrines`, `caravan`, `wanted` are written only by `main.gd:_update_zone`, which runs in team
  and Brawl fights, so nothing ever emptied them. The failing assertion before the fix:
  "Capture the Flag: 3v3 vs CPU -> main menu: the menu background still draws expected , got
  flags 2, shrines 3, wanted 6". Fix: `clear()` resets all six arrays (every match start and
  the menu background go through `_new_sim`, which calls it); a replay seek, which also clears
  fx, now re-runs `_show_pads()` and `_update_zone()` so a paused team replay keeps its marks
  (and gets its Deathmatch pads back, which a seek already lost before). No sim or rules change.
- New test `tests/test_mode_objects.gd` (5 tests): (a) CTF, Caravan and Brawl each followed by
  Main menu and a Versus 1v1 must leave no mode object; (b) every offline MODES entry built
  with the expected sim-object set read from `data/rules/*.json` (flags / bases only for ctf,
  shrines iff the rules have a block, track only for caravan, zone for crater or caravan, the
  pinned arena for ctf / caravan, never Twin Keeps or Caravan Pass otherwise); (c) CTF's two
  bases and flags apart, distinct spawns per side for every team rules id at every size. Skips
  showcase, trials, drills, online and replay (need a coach, server or saved replay).
- Targeted run after the fix: 273 passed. Smoke `--mode=52` and `--mode=0`: no SCRIPT ERROR.
- By design, not a bug: Brawl, Chaos Cup and King of the Crater (including Crater 1v1) put a
  centre haste / might shrine on all four pickable maps (`brawl.json`, `crater.json` carry a
  "shrines" block). That is the "speed boost on a 1v1 map" → Open questions.
- Not covered by a test: online starts (they go through `_new_sim`, so they get the fix).

### Part 2: pit footprint

Details: `docs/qa/part2-pits.md` (merged b107334; code 142df6a, docs 900167f).

- **major**, fixed: pit detection was a single point test at the fighter's origin
  (`match_sim.gd:_check_falls` → `terrain.is_hole_at(c.pos)`; the walking guard in
  `CreatureSim._move` the same), so any fighter whose centre crossed one 8-unit pit cell fell,
  whatever its size. New rule, one shared function `TerrainGrid.footprint_falls(pos, radius)`:
  a fighter falls only when at least `fall_fraction` (0.5) of nine fixed sample points (the
  centre plus eight on the body circle at `radius x fall_radius_mult`, 1.0; a constant table,
  no trig at run time) are over pit cells. Knobs in the new `data/rules/falls.json` (keys in
  MECHANICS.md); `fall_radius_mult` 0 gives the old rule back bit for bit. Applied in
  `_check_falls`, the walking guard (walk, lunge, non-leap dash, ram dodge, taunt drag), blink
  landings, and the CPU's `_lands_safe`, `_cross_lands` and the ram stop, so CPU and sim agree.
  Left alone: the boulder hazard's own centre test (not a fighter), plants, steering probes,
  pickups; `NavGrid.PIT_CELLS` stays 2 (cautious: a CPU may walk round a crack it could cross).
- What the defaults do: nobody falls through a 1- or 2-cell hole or a one-cell crack; a 2x2
  hole drops radius 9-10 fighters centred in it; a 3x3 hole drops everyone centred, radius 13
  survives at the lip; a wide chasm drops anyone half over it, nobody a quarter over.
  Side effect to playtest: one-cell cracks are now walked over (they used to stop a walk).
- `min_pit_cells` skipped: at mult 1.0 one or two cells can never hold five of nine points,
  and it would be a second rule for the CPU to copy; only worth it if the mult goes under ~0.5.
- New test `tests/test_pit_footprint.gd` (7 tests, a 38-row table: radius 9 / 10 / 13 over
  holes of 1, 2, 3x3, 4x4 cells and a chasm strip, centred / half / three-quarters / a quarter
  over; the stepped match, the walking guard, the CPU's `_lands_safe`, mult 0 = old rule). Two
  old tests assumed a single cell is lethal and got wider pits (`test_combat` walking edge,
  `test_pete` Big Heist). Targeted sets: 134 + 16 (balance) + 372 + 241 passed.
- Determinism fingerprint changes as expected (the seeded Cairn vs Culvert match now has two
  falls, the old rule had none): `0ded643a…` → `31bf3294128c5f0e0527095b2ed16a96dfa5f79e3e1082eb3c8f4fdd51ee86f1`.
  Balance pins unchanged (Pete vs Cairn 15/20, Cerebro vs Hissy 8/8, vs Culvert 6/8, vs
  Craglash 8/8). NET_VERSION 75 → 76 (`falls.json` joins `data_hash`; same bump covers the
  Twin Keeps map change). The server needs a rebuild after this merges.
- Readability at 32 px (hand check, no art changed): on the tiled maps a lone pit is one 16
  px overlay tile; under the new rule the smallest lethal hole is 2x2 (32 px), 3x3 for radius
  13, so a single cell's look matters less. Still on the hand list.
