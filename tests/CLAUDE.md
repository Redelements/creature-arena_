# tests: the runner, the benches, CI

`$G --headless --path . --script res://tests/run_tests.gd` runs every `tests/test_*.gd`;
`TEST_ONLY=culvert,combos` is a substring match on file names. The full suite takes several
minutes. Each `test_*` method runs on a fresh `TestCase` (`test_case.gd`: `assert_*`, sim
helpers `run`, `tap`, `run_until`). A new file extending `TestCase` needs no registration.
Engine and script errors count as failures; exit code 1 on any failure. Run `--import`
after adding a `class_name`. Each file's header comment says what it pins (listed under Files below).
`TEST_QUIET=1` prints only failures and the summary: use it, then rerun a failing file
without it for detail. `TEST_SHARD=k/N` runs every Nth file of the sorted list from the
kth (k from 1): CI runs three shards side by side (`tests.yml`), which splits the suite
about evenly (the slowest files, `test_server_teams`, `test_server_fuzz`, `test_rage`,
`test_journey`, `test_ai`, `test_balance`, land on different shards by name).

## Conventions and gotchas

- `sim.events` is cleared every step: to see events over several ticks, collect them each
  step (see `tests/test_stamina.gd:_step`).
- The training dummy doesn't flinch; compare against a control run rather than assuming a
  reaction state.
- Balance pins (`test_balance.gd`) are seeded Normal-vs-Normal CPU matches (never Rage;
  `test_rage.gd` only checks how Rage plays): a rules or tuning change can move them. Measure with the benches before relaxing one, and say why
  in the test's comment.
- Rollback coverage: `test_rollback.gd` checks every declared variable is saved;
  `test_rollback_fuzz.gd` plays every mode (hazards, shrines, the crown) with Normal CPUs and
  input mashing, restoring snapshots at random ticks and comparing digests with a fresh replay.
  About 30-40 s by default; `TEST_FUZZ_LONG=1` (ten times the seeds and ticks) is the deep soak
  to run after touching `snapshot()`/`restore()` or adding mode state. A digest failure there is
  a real rollback bug; a "never reached" failure is coverage only (retune that mode's entry).
- Scratch probes (a `SceneTree` script run with `--script`) are fine for investigating;
  delete them before committing.

## Benches (not tests)

- `bench_fighter.gd`: why one fighter wins or loses (`--fighter=sno`, `--foes=`,
  `--seeds=`, `--a=`, `--b=`, `--arena=`, `--mutators=pit_floor`): moves thrown, landed and blocked, damage dealt and taken,
  hits taken mid-move, pit falls, time guarding, the moves that hit it most, time with no walk to the foe, pits crossed in the air.
- `bench_cpu.gd`: CPU tier win rates: `--matrix` (every pair at `--a`, default 1 = Normal; balance never uses Rage), `--pairs`,
  `--seeds`, `--only=<id>` (with `--matrix`: just that fighter's row, same seeds), `--slot=<role>` (the slot bench: each fighter in the tank, mage or assassin slot of the reference team culvert / cerebro / pete, against that team, all Normal CPUs; team win rate, draws half; R9 in `docs/plans/council-backlog.md`), `--detail` (per foe: share of ticks at `ai.range` spacing, stamina-empty ticks, guard breaks taken), `--arena=ID`, `--teams=3` (3v3 tank/mage/assassin a side: win rate, target and focus switches a minute, spacing; `--intent=a` gives only the first-picks side the team focus, `--intent=off` nobody), `--combat` (Rage vs Rage over the roster: each fighter's damage share by move type, combo length and variety, Surges a minute; baseline in `docs/plans/combat-metrics.md`). Six games a pair at `--seeds=3` is
  noisy; `--only=<id> --seeds=6` plays 132 games.
- `bench_sim.gd`: rollback cost. `bench_sinkhole.gd`: Sinkhole pacing. `bench_caravan.gd`:
  Caravan pacing with Normal CPUs (each round's push, checkpoints, rockslides, digging, healing; a summary per size: push, finishes, time an attacker / a defender is at the caravan, the caravan's state; `--plan=off` plays it without the CPU's Caravan plan). `bench_ctf.gd`:
  Capture the Flag pacing with Normal CPUs (`--seeds`, `--sizes=3,4`, `--level`,
  `--set=key:value` to try a tuning): match length, score, and every play's count.
  `bench_modes.gd`: every mode's pacing on one yardstick, Normal CPUs (`--modes=team2,tdm3,brawl4,...`,
  `--seeds`, `--shrines=data|on|off`, `--shrine-set=key:value`, `--set=key:value` (a top-level rules number, e.g.
  `spree_at:0`, `crown:0`, `crown_points_to_win:20`), `--shrine-spots=0.5/0.25;0.5/0.75`, `--arena=ID`,
  `--mutators=damage_mult:0.67` (or a mutators.json id), `--rows`, `--pits`: pit falls, pits crossed in the air, time with no walk to a foe): match length, stalemate share,
  fights a minute, KOs, comebacks from behind at half time, shrine claims, time-outs, how often the first KO's
  side won, sprees, shutdowns, crown changes, the Caravan's push (definitions and results in
  `docs/plans/mode-metrics.md`). `bench_spacing.gd`: how far apart fighters fight. `bench_ai_cost.gd`: what a tick costs in a big
  team match (`--mode=ctf|caravan|sinkhole`, `--size=4`, `--level=3`, `--threads=off`): CPU thinking
  and sim step percentiles; a stutter is the tail (p99.9, max). In a real window, `--perf` does the
  same for frames and ticks.
- Parallel Godot runs need separate `APPDATA` (Windows) / user dirs, or `user://` collides.
- `tools/smoke_sweep.py` (not a bench): every mode on the four map choices headless with all
  hazards on, failing on SCRIPT ERROR / Parse Error / Failed to load; about four minutes. Run it
  with the suite and `--sim-check` before a PR that touches many modes.

- `test_licenses.gd`: every bought-art file LICENSES.md lists exists and none is under `assets/ui/`
  or an icon (Szadi's licence forbids the art in a logo or mark); the wordmark is generated.

## CI

- `.github/workflows/tests.yml`, every push and PR: the codebase map check
  (`python3 tools/codebase_map.py --check`), then download Godot 4.7.2, `--import`, run the tests.
- `.github/workflows/determinism.yml`, every push and PR: the stock editor binary on Linux and on
  Windows plays `--sim-check` (seed 20261010); the `cross-platform-determinism` job fails if the
  digests differ. Only the two digest files are uploaded.
- `.github/workflows/playable-build.yml`, pushes to main and manual runs (never a PR by itself: on a
  public repository anyone signed in can download an artifact): export Windows + Linux, smoke-test
  the Linux build (cairn showcase, then `--server=7777`; fails on SCRIPT ERROR / Parse Error /
  Failed to load), `--sim-check` on the Linux build, upload the builds (kept 3 days); a debug
  Android APK (job `android`: SDK from the runner's `ANDROID_HOME`, a fresh debug key); on a
  manual run the `comment` job links all three on the branch's open PR, if it has one.
- `.github/workflows/nightly.yml`, 06:00 UTC and on demand (`workflow_dispatch`), never on PRs: `balance`
  runs `bench_cpu.gd --matrix` and `--pairs` (the `test_balance.gd` pairs) at Normal and `bench_modes.gd`,
  uploaded as the `balance-matrix` and `mode-pacing` artifacts (fails only on a crash, never on the numbers);
  `determinism` runs `--sim-check` for twelve fixed seeds on Linux and Windows (the stock editor
  binaries) and `compare` fails if any digest differs; `summary` puts the digest table on the run page.
  A long `TEST_ONLY=rollback_fuzz TEST_FUZZ_LONG=1` step turns on by itself once the rollback fuzz test (another PR) lands.
